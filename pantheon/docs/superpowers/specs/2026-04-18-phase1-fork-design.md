# Phase 1 — Open WebUI Fork & Sanctuary Integration Design
Date: 2026-04-18
Status: Approved

---

## 1. Scope

This spec covers the Phase 1 minimal Open WebUI fork integration for Pantheon. It produces a working local instance with:

- Open WebUI pulled in as a git subtree and running via Docker Compose
- pantheon-core running as a sidecar FastAPI service
- Prompt isolation enforced — active Sanctuary's harness identity is the sole system prompt
- Basic Sanctuary selector as primary navigation
- Vault logging pipeline writing session turns to the Athenaeum in real time

This is Phase 1 only. Hermes message queue, Hades nightly consolidation, Hecate context classification, and Mnemosyne vector search are Phase 2 concerns and are not implemented here.

## 3. Service Architecture

Two services, one Docker Compose file.

### open-webui

Runs the forked Open WebUI application. Receives browser traffic on port 3000. Knows the pantheon-core service URL via environment variable. Modified minimally — two files changed from upstream, both tracked in `UPSTREAM_CHANGES.md`.

### pantheon-core

Runs a FastAPI application exposing the Pantheon API. Internal only — exposed on port 8000 inside the Docker network, not reachable from the host or browser. Mounts the Athenaeum directory as a live volume so vault writes land directly on the filesystem.

```yaml
services:
  open-webui:
    build: ./open-webui
    ports:
      - "3000:8080"
    environment:
      - PANTHEON_CORE_URL=http://pantheon-core:8000
    depends_on:
      - pantheon-core

  pantheon-core:
    build: ./pantheon-core
    volumes:
      - ./Athenaeum:/athenaeum
    environment:
      - PANTHEON_HARNESS_DIR=/athenaeum/Codex-Pantheon/harnesses
      - ATHENAEUM_ROOT=/athenaeum
    expose:
      - "8000"
```

## 4. pantheon-core API

Three endpoints for Phase 1:

| Method | Path | Purpose |
|--------|------|---------|
| `GET` | `/sanctuaries` | Returns all Sanctuary configs for the selector UI |
| `GET` | `/sanctuary/{id}/prompt` | Returns assembled harness identity string for the given Sanctuary |
| `POST` | `/sanctuary/{id}/log` | Appends one conversation turn to the session vault file |

### Sanctuary config files

Stored in `Athenaeum/Codex-Pantheon/harnesses/sanctuaries/` as YAML. The `GET /sanctuaries` endpoint reads all files in that directory and returns them grouped by god.

### Prompt assembly

`GET /sanctuary/{id}/prompt` loads the Sanctuary config, finds its harness file, runs the existing harness loader (resolving extends chain), and returns only the `identity` field as a plain string. The result is cached in memory per harness filename and invalidated when Hera writes a change (Phase 2). For Phase 1 the cache is never invalidated — a service restart clears it.

### Vault logging

`POST /sanctuary/{id}/log` accepts `{ "role": "user"|"assistant", "content": "..." }`. On the first call for a new session it creates the session file in the Sanctuary's configured vault path, writes the frontmatter header, then appends the turn. Every subsequent call appends immediately — no buffering. Session ID is a UUID generated by the Open WebUI middleware when the Sanctuary is opened and passed in the request body alongside role and content.

Session file format:
```markdown
---
sanctuary: The Studio — Lyric Writing
god: Apollo
studio: lyric-writing
timestamp: 2026-04-18T14:32:00
---

[User]: prompt content here

[Apollo]: response content here

---
```

## 5. Open WebUI Modifications

Two files modified in `open-webui/`. Both logged in `UPSTREAM_CHANGES.md`.

### pantheon_middleware.py (new file in open-webui/backend/)

FastAPI middleware that intercepts all chat completion requests.

**On session open (Sanctuary selected):**
- Reads the active Sanctuary ID from the session cookie
- Calls `GET /sanctuary/{id}/prompt` on pantheon-core
- Stores the returned identity string in the session for the duration
- Generates a UUID session ID and stores it in the session

**On each chat completion request:**
- Replaces the system prompt in the request body with the stored harness identity
- The global system prompt from Open WebUI's settings is discarded — never included
- If no Sanctuary is active, calls `GET /sanctuary/hecate-default/prompt` as fallback

**After each completed turn:**
- Calls `POST /sanctuary/{id}/log` with role and content for both the user message and the assistant response

**On session close / Sanctuary switch:**
- Clears the stored prompt and session ID from session state

### Open WebUI app startup (one line changed)

Registers `pantheon_middleware.py` as middleware in Open WebUI's FastAPI app. This is the only change to existing Open WebUI files.

## 6. Sanctuary Selector UI

Two frontend changes to Open WebUI's Svelte codebase, tracked in `UPSTREAM_CHANGES.md`.

### Sanctuary selector (replaces workspace/model sidebar)

- Calls `GET /sanctuaries` on load
- Renders Sanctuaries grouped by god with accent color and icon from config
- Clicking a Sanctuary sets the active Sanctuary ID in the session and triggers a prompt load
- Active Sanctuary is visually highlighted

### Global system prompt field removed

The global system prompt input in Open WebUI's settings is deleted — not hidden, not disabled. Removed from the component and from the settings save/load logic. Its existence invites misconfiguration and violates prompt isolation.

## 7. Error Handling

| Error | Behavior |
|-------|---------|
| pantheon-core unreachable at startup | open-webui container retries via depends_on health check; user sees loading state |
| Harness file not found for active Sanctuary | Middleware returns error to UI: "Sanctuary unavailable — harness missing"; session does not open |
| Vault write failure | Session continues; error logged to stderr; user notified at turn end with non-blocking toast |
| `/sanctuaries` returns empty | Selector shows "No Sanctuaries configured" with link to harness directory |
